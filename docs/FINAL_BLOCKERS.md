# Final blockers, limits and what not to claim

## Fixed in this audit (small, separate commits are in the Git log)
1. A crashed scanner or stage (`SCANNER.ERROR.*`, `INTAKE.STAGE.ERROR`) only added points; in dev it could still end in "allow". Now at least a quarantine in every environment (`policy/engine.py`; `tests/test_submission_regressions.py`).
2. Inert `127.0.0.1` URLs counted as personal data and blocked the demo dataset. Loopback, private and documentation addresses are no longer PII; a public IP alone no longer blocks (`inspect/dataset_pii.py`, `policy/engine.py`).
3. The stage message "Reviewer ran" appeared when **no model request was made**. It now says "No model request was made ..." (`intake/inspectors.py`).
4. A declared parent that the weights contradicted was silently accepted. Now `MODEL.PARENT.CLAIM_MISMATCH` (medium) (`tests/test_declared_parents.py`).
5. `lineage revoke` could never work against an auth-enabled server (no token, fixed server). Fixed and demonstrated live (`lineage/cli.py`).
6. A failed hub fetch was recorded as `@0.0.0`; it is now recorded under the requested name. The demo's "Try" buttons pointed at sources the demo hub does not have (HTTP 404); they now use ones it has.
7. Four missing creator-passport tests added (expired, file changed after signing, modified payload, multi-key publisher).

## Must not be claimed
* **GPU checks (spectral, behaviour, notary): not run on this version.** Code and fake-worker tests only. The worker also reads model files from its own disk and knows 7 bank models.
* **Live LLM review: no request has been made in this audit** (no credentials or route). Hosted tests are mocked. The model in the frozen benchmark (Nemotron-Nano on vLLM) differs from the hosted default (`nemotron-3.5-lightning-30b-a3b`).
* **Real Hugging Face acquisition: not run** (no route from this environment). `tests/test_real_hub.py` is off by default; run `LINEAGE_TEST_REAL_HUB=1 uv run pytest tests/test_real_hub.py -q` on your Mac.
* **Parent identification is limited screening.** Local parent search compares only admitted models on the same host, by whole-tensor relative L2 (threshold 0.5; one false parent in 39 toy trials). Hub parent compares only the first 512 embedding rows of a named base. A declared parent is a statement; its content is checked only against the host's reference set. `MODEL.PARENT.NO_CLAIMED_BASE` means "nothing named", not "no parent". `MODEL.PARENT.IDENTICAL` creates no parent edge.
* **Detection is not comprehensive:** regex prompt-injection and PII rules, Python-only AST/taint, template instruction detection by regex, dataset poisoning at about 1% mostly missed, tool return values not scanned. Held-out benchmark: 28/40 on our own synthetic set (`CLAIMS.md`); 88/90% are post-hoc; nothing measures real attacks.
* **"Verify passport" in the dashboard checks the registry's record** (signature, ancestors, revocation, expiry), not file hashes.
* **Complete lineage capture:** `lineage run` records Python file opens, packages and outputs, plus `lineage.load` calls; native readers, downloads and unwrapped loads are missed; it records, it does not enforce.
* **Enforcement outside Lineage's paths:** direct `from_pretrained`, `torch.load` or `pip install` from pypi.org bypass it. Block those at the network.
* Agents receive only provenance, parent-chain and generic checks (no agent-specific scanner).

| Artifact type is chosen by the user, not detected | wrong-type intake | detect from files and warn | feature, not a fix |
